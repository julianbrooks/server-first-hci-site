Appendix B: Enough Kotlin to read this book

This appendix is for a reader who knows Java, Python or JavaScript and has not met Kotlin; by the end you can read every file the chapters include, and you will not have written a line.

The book's code is Kotlin on the JVM, served by Ktor and rendered by Pebble. The chapters say what each piece does; this page says what the syntax means, with the real lines from the reference code as the examples. If a construct is not here, the Kotlin documentation's basic syntax page covers it in a screen or two (JetBrains, no date a).

B.1 Declarations

src/main/kotlin/Main.kt
/** Starts the server. The port comes from the PORT environment variable and defaults to 8080. */
fun main() {
    val port = System.getenv("PORT")?.toIntOrNull() ?: 8080
    embeddedServer(Netty, port = port, host = "0.0.0.0") { module() }.start(wait = true)
}

val declares a name that is assigned once; var declares one that can be reassigned. Almost everything in this code is a val. The type is inferred from the right-hand side, so port is an Int without saying so; a type is written after a colon only where inference needs help or a reader does. A function is fun, its parameters are name: Type, and a return type follows the parameter list after a colon; main returns nothing and says nothing. Named arguments, port = port, make a call with several parameters readable, and { module() } after the brackets is a lambda passed as the last argument, which the section on lambdas comes back to.

B.2 Null safety

A type in Kotlin says whether it can hold null. String cannot; String? can, and the compiler will not let you call a method on it until you have dealt with the null.

src/main/kotlin/storage/TaskStore.kt
    /** Flips completed and returns the updated task, or null when there is no such task. */
    fun toggleComplete(id: String): Task? {
        val task = getById(id) ?: return null
        val updated = task.copy(completed = !task.completed)
        update(updated)
        return updated
    }

getById returns Task?, a task or null. ?: return null is the elvis operator: if the left side is null, do the right side, which here leaves the function. In Main.kt above, System.getenv("PORT")?.toIntOrNull() ?: 8080 reads: the variable, or null; converted to an Int if it is one, or null; and if any step gave null, 8080. The ?. is a safe call, which gives null instead of throwing when its receiver is null. A route handler uses the same shape to answer a request for a task that does not exist.

src/main/kotlin/routes/TaskRoutes.kt
private suspend fun ApplicationCall.deleteTask(store: TaskStore) {
    val task = store.getById(parameters["id"].orEmpty()) ?: return respond(HttpStatusCode.NotFound)
    store.delete(task.id)
    if (isHtmxRequest()) {
        // Nothing replaces the item, so the outerHTML swap removes it. The status is the only content.
        respondHtml(renderStatus("Deleted \"${task.title}\"."))
    } else {
        seeOther(tasksPath())
    }
}

?: return respond(HttpStatusCode.NotFound) sends the 404 and leaves the handler in one expression. You will also see !!, which asserts a value is not null and throws if it is; the reference code uses it only in tests, where a null is a failed test anyway.

B.3 Functions and their bodies

src/main/kotlin/routes/TaskRoutes.kt
private fun ApplicationCall.renderAddForm(title: String? = null, error: String? = null): String =
    renderTemplate("tasks/_add_form.peb", TITLE_LIMITS + mapOf("oob" to true, "addTitle" to title, "addError" to error))

/** The out-of-band update for the live region. The message is text; the template does the HTML. */
private fun ApplicationCall.renderStatus(message: String, isError: Boolean = false): String =
    renderTemplate("tasks/_status.peb", mapOf("message" to message, "error" to isError))

private suspend fun ApplicationCall.respondHtml(html: String) = respondText(html, ContentType.Text.Html)

A function whose body is one expression is written with = and no braces or return. A parameter can have a default, title: String? = null, and a caller leaves it out or names it. suspend marks a function that can pause without blocking a thread, which is how Ktor serves many requests at once; for reading the code it changes nothing except that only another suspending function, or a route handler, can call it. private limits the function to its file. The receiver before the dot, ApplicationCall., is the next section.

B.4 Extension functions

src/main/kotlin/Templating.kt
/**
 * Renders a template under resources/templates with [context], adding `isHtmx` so the
 * layout can use it without every route passing it.
 */
fun ApplicationCall.renderTemplate(name: String, context: Map<String, Any?> = emptyMap()): String {
    val engine = application.attributes[PebbleEngineKey]
    val enriched = context + mapOf("isHtmx" to isHtmxRequest())
    return StringWriter().also { engine.getTemplate(name).evaluate(it, enriched) }.toString()
}

fun ApplicationCall.renderTemplate(...) adds a method to Ktor's ApplicationCall type without changing it. Inside, this is the call, so application and request are the call's own properties. A route then writes call.renderTemplate("tasks/index.peb", context) as if Ktor shipped it. The code uses this shape everywhere: the route helpers above are extensions on ApplicationCall, and each routes file is an extension on Route.

src/main/kotlin/routes/HealthCheck.kt
package routes

import io.ktor.http.ContentType
import io.ktor.server.response.respondText
import io.ktor.server.routing.Route
import io.ktor.server.routing.get
import java.time.Instant

/** A one-line JSON answer for checking that the server is up, for example through a forwarded port. */
fun Route.configureHealthCheck() {
    get("/health") {
        call.respondText("""{"status":"ok","time":"${Instant.now()}"}""", ContentType.Application.Json)
    }
}

B.5 Data classes

src/main/kotlin/model/Task.kt
/**
 * One task. The id is a UUID string, so a task keeps its identity when the CSV file is
 * rewritten. Nothing here identifies a person.
 */
data class Task(
    val id: String = UUID.randomUUID().toString(),
    val title: String,
    val completed: Boolean = false,
    val createdAt: LocalDateTime = LocalDateTime.now(),
) {
    /** The shape templates see. Dates arrive formatted so templates do no formatting. */
    fun toPebbleContext(): Map<String, Any> =
        mapOf(
            "id" to id,
            "title" to title,
            "completed" to completed,
            "createdAt" to createdAt.format(DISPLAY_FORMAT),
            "createdAtISO" to createdAt.format(DateTimeFormatter.ISO_LOCAL_DATE_TIME),
        )

A data class is a class whose purpose is to hold values. Its constructor is in the header, each parameter with val becomes a read-only property, and defaults fill in what a caller omits, so Task(title = "Milk") is a complete task with a fresh id. The compiler writes equals, hashCode, toString and copy. Because the properties are read-only, changing a task means making a changed copy: task.copy(completed = !task.completed) in TaskStore above gives a new task with one field different and the rest the same. A method body goes in the braces after the header, as toPebbleContext does. Comments between /** */ are documentation comments, as in Java.

B.6 when and sealed classes

src/main/kotlin/model/Task.kt
        fun validate(title: String): ValidationResult =
            when {
                title.isBlank() -> failure("blank_title")
                title.length < MIN_TITLE_LENGTH -> failure("min_length")
                title.length > MAX_TITLE_LENGTH -> failure("max_length")
                else -> ValidationResult.Success
            }

when is a switch that is also an expression. Without a subject, each branch is a condition and the first true one wins; else is the default. Here the whole function is one when, and its value is the function's result. validate returns a ValidationResult, which is a sealed class.

src/main/kotlin/model/Task.kt
sealed class ValidationResult {
    data object Success : ValidationResult()

    data class Error(val code: String, val message: String) : ValidationResult()
}

A sealed class has a fixed set of subclasses, all in this file, so a when over one can be exhaustive and the compiler checks that it is. data object is a singleton with a readable toString; data class Error carries two values. A route matches on them with is.

src/main/kotlin/routes/TaskRoutes.kt
private suspend fun ApplicationCall.addTask(store: TaskStore) {
    val title = receiveParameters()["title"]?.trim().orEmpty()
    when (val result = Task.validate(title)) {
        is ValidationResult.Error ->
            if (isHtmxRequest()) {
                // Nothing for the list. The form comes back out of band with the error, and the live region announces it.
                respondHtml(renderAddForm(title, result.message) + renderStatus(result.message, isError = true))
            } else {
                seeOther(tasksPath(error = result.code, title = title))
            }
        ValidationResult.Success -> {
            val task = Task(title = title)
            store.add(task)
            if (isHtmxRequest()) {
                respondHtml(
                    renderTemplate("tasks/_item.peb", itemContext(task)) +
                        renderAddForm() +
                        renderStatus("Added \"${task.title}\"."),
                )
            } else {
                seeOther(tasksPath())
            }
        }
    }
}

when (val result = Task.validate(title)) binds the result and matches on it in one line. In the is ValidationResult.Error branch the compiler knows result is an Error, so result.message and result.code need no cast; this is a smart cast. if is an expression too, and both branches here are statements that respond.

B.7 Lambdas

src/main/kotlin/Main.kt
/** One console line per request: method, path and status. */
fun Application.configureLogging() {
    install(CallLogging) {
        format { call -> "${call.request.httpMethod.value} ${call.request.path()} - ${call.response.status()}" }
    }
}

A lambda is code in braces. If it takes a parameter, the name comes first and then ->; if it takes one and you do not name it, the parameter is it. When a lambda is a function's last argument it is written after the closing bracket, and if it is the only argument the brackets go: install(CallLogging) { ... } passes a configuration lambda, and format { call -> ... } passes a lambda that receives each call. The collection functions take lambdas the same way.

src/main/kotlin/storage/TaskStore.kt
    /** Returns false when there was no task with that id. */
    fun delete(id: String): Boolean {
        val tasks = getAll()
        val remaining = tasks.filterNot { it.id == id }
        if (remaining.size == tasks.size) return false
        writeAll(remaining)
        return true
    }

tasks.filterNot { it.id == id } keeps every task whose id differs. map { it.toPebbleContext() }, find { ... }, none { ... } and forEach { ... } read the same way, and Task::messageFor is a reference to a function where a lambda would do.

B.8 Scope functions

src/main/kotlin/Templating.kt
fun buildPebbleEngine(): PebbleEngine =
    PebbleEngine.Builder()
        .loader(ClasspathLoader().apply { prefix = "templates/" })
        // Every {{ value }} is HTML-escaped. This is what makes rendering through templates safe.
        .autoEscaping(true)
        // Templates are re-read on every request, so edits show without a restart.
        .cacheActive(false)
        .strictVariables(false)
        .build()

Four small functions take a lambda and apply it to the value before them. apply { ... } runs the lambda with the value as this and returns the value, so ClasspathLoader().apply { prefix = "templates/" } configures and hands back the loader in one expression. also { ... } runs the lambda with the value as it and returns the value; renderTemplate above uses it to evaluate into a StringWriter and then return that writer's text. let { ... } runs the lambda with the value as it and returns the lambda's result, and ?.let is the usual way to transform a value only when it is not null. use { ... } is for anything closable, like Java's try-with-resources.

B.9 String templates

src/main/kotlin/routes/TaskRoutes.kt
            if (isHtmxRequest()) {
                respondHtml(
                    renderTemplate("tasks/_item.peb", itemContext(task)) +
                        renderAddForm() +
                        renderStatus("Added \"${task.title}\"."),
                )

Inside a string, $name inserts a variable and ${expression} inserts anything else, so "Added \"${task.title}\"." is the message with the title in it. A string in triple quotes, as in HealthCheck.kt, is raw: no escapes, line breaks allowed, templates still expanded. Note what this message is for: it is text handed to a template, which escapes it. The code never builds HTML this way, and Chapter 1 says why.

B.10 object and companion object

src/main/kotlin/model/Task.kt
    companion object {
        const val MIN_TITLE_LENGTH = 3
        const val MAX_TITLE_LENGTH = 100

        private val DISPLAY_FORMAT = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm")

        /** Messages by validation code. The code is what a redirect carries and what the metrics record. */
        private val MESSAGES =
            mapOf(
                "blank_title" to "Enter a title.",
                "min_length" to "Title must be at least $MIN_TITLE_LENGTH characters.",
                "max_length" to "Title must be $MAX_TITLE_LENGTH characters or fewer.",
            )

Kotlin has no static. A companion object inside a class holds what Java would make static: constants, factories, lookups. const val is a compile-time constant; a plain val in an object is computed once when the object is first used. From outside, Task.MIN_TITLE_LENGTH and Task.validate(title) read as static members. A top-level object is a singleton, which the tests use.

B.11 How a Ktor route block reads

src/main/kotlin/routes/TaskRoutes.kt
fun Route.configureTaskRoutes(store: TaskStore) {
    get("/") { call.seeOther("/tasks") }
    get("/tasks") { call.listTasks(store) }
    post("/tasks") { call.addTask(store) }
    // TODO Week 6 Lab 1: add delete. HTMX sends DELETE /tasks/{id}; a form without JavaScript
    // can only POST, so it needs POST /tasks/{id}/delete as well. Both call one handler.
}

routing { ... } in Main.kt builds the routing table from a lambda, and inside it configureTaskRoutes(store) is called as an extension on the Route being built. get("/tasks") { ... } registers a handler: a lambda that runs for each matching request. Inside the handler call is a property of the lambda's receiver, which is why it appears without being declared; call.listTasks(store) then hands the work to one of the private extension functions above. Every handler is a suspending lambda, and parameters["id"] reads the {id} segment of the path. The Ktor documentation describes the routing tree and its matching rules (JetBrains, no date b).

B.12 How a Pebble context map is built

src/main/kotlin/routes/TaskRoutes.kt
private val TITLE_LIMITS = mapOf("minTitleLength" to Task.MIN_TITLE_LENGTH, "maxTitleLength" to Task.MAX_TITLE_LENGTH)

/** Every task, newest first. */
private fun listContext(store: TaskStore): Map<String, Any?> =
    TITLE_LIMITS + mapOf("tasks" to store.getAll().asReversed().map { it.toPebbleContext() })

/** Builds /tasks with only the query parameters that carry information. */
private fun tasksPath(error: String? = null, title: String? = null): String {
    val params =
        buildList {
            if (error != null) add("error=${error.encodeURLParameter()}")
            if (title != null) add("title=${title.encodeURLParameter()}")
        }
    return if (params.isEmpty()) "/tasks" else "/tasks?" + params.joinToString("&")
}

A template's context is a Map<String, Any?>: string keys, any value or null. mapOf("a" to 1, "b" to 2) builds one, and to is an ordinary function that makes a pair, which is why it needs no quotes or colons. + merges two maps into a new one, with the right-hand map winning when a key is in both; renderTemplate above adds isHtmx to whatever a route passed. buildList { ... } is the same idea for lists: add inside the lambda, get a read-only list back. asReversed() gives a reversed view without copying. Task.toPebbleContext() is the other half: the data class turned into the map a template reads, with dates already formatted, so Appendix C can treat every value as a string, a number, a boolean, a list or a map.

That is the whole of the Kotlin the chapters assume. When a line still resists, the Kotlin documentation is organised by construct and the examples are short (JetBrains, no date a).
