Appendix C: Pebble

This appendix covers the Pebble template syntax the book uses and ends with a cheatsheet for finding one row.

Pebble is a template engine for the JVM with syntax in the Twig and Jinja family; the reference code uses version 3.2.4 (Pebble Templates, no date). A template is a text file, in this book always HTML, with expressions, tags and comments embedded in it. The server fills it from a map of values and sends the result. Every page and every fragment the application sends is a template, and nothing is built by joining strings in Kotlin, which is what keeps the escaping in one place.

C.1 How the engine is set up

src/main/kotlin/Templating.kt
/** Builds the engine the application uses. The template smoke test uses the same one. */
fun buildPebbleEngine(): PebbleEngine =
    PebbleEngine.Builder()
        .loader(ClasspathLoader().apply { prefix = "templates/" })
        // Every {{ value }} is HTML-escaped. This is what makes rendering through templates safe.
        .autoEscaping(true)
        // Templates are re-read on every request, so edits show without a restart.
        .cacheActive(false)
        .strictVariables(false)
        .build()

Three settings matter. autoEscaping(true) escapes every { } for HTML; the raw filter turns that off for one expression, and the reference code never uses it. cacheActive(false) re-reads a template on every request, so an edit shows on the next reload without a restart; a deployed application would turn the cache on. strictVariables(false) renders a variable that is not in the context as nothing rather than throwing. That last one is a trade: a misspelt variable name produces an empty gap on the page, not an error, and the template test does not catch it. When a value is missing from a page, compare the spelling in the template with the key in the Kotlin map before looking anywhere else.

C.2 Delimiters

Delimiter Does Example from the code
{ expression } Outputs the value, escaped { task.title }
{% tag %} Logic: if, for, extends, block, include {% for task in page.items %}
{# comment #} Nothing; it is not in the output {# The one live region on the page. #}

The reference templates use comments to say why a line is there, and that is what they are for.

C.3 Variables and the context

The context is a Kotlin Map<String, Any?> whose keys become variable names. The dot in task.title reads a map key, a public property or a getter, whichever the value has. renderTemplate adds isHtmx to every context, as Chapter 1 shows. The reference code hands templates maps of strings, booleans, numbers, lists and maps, built by the toPebbleContext() functions on Task and Page, so a template never calls a method to format a date or a number; the value arrives ready. A template that reaches into an object to format something is a template that breaks when the object changes.

C.4 Output and escaping

With autoEscaping on, a title of <b>bold</b> & "quoted" renders as &lt;b&gt;bold&lt;/b&gt; &amp; &quot;quoted&quot;, inside an attribute as well as in text. The route test titles are escaped everywhere they appear checks exactly that. Escaping is HTML escaping. A value that goes into a URL needs the urlencode filter instead, as _pager.peb does with the query: a b&c becomes a+b%26c.

C.5 Control flow

if takes an expression and ends with endif; between them elseif and else are optional. Comparisons are ==, !=, <, >, <=, >=; and, or and not combine them; brackets group. A non-null, non-empty value is true, so {% if query %} in _list.peb means "if a filter is on". Tests follow is: is null, is not null, is empty, is defined.

for iterates a list and ends with endfor. The branch for an empty list is {% else %}, placed before {% endfor %}. The 2025 text taught {% empty %}, which is Django's tag; Pebble rejects it at parse time with Unexpected tag name "empty" and the template's name and line. Inside the loop, loop.index counts from zero, loop.revindex counts down to zero, loop.first and loop.last are booleans and loop.length is the size; loop.index0 is Twig and renders as nothing here.

C.6 Inheritance

src/main/resources/templates/errors/404.peb
{% extends "_layout/base.peb" %}

{% block title %}Page not found{% endblock %}

{% block content %}
<h1>Page not found</h1>
<p>There is nothing at this address. <a href="/tasks">Go to the task list</a>.</p>
{% endblock %}

extends names the parent, which is _layout/base.peb for every page in the application. block fills a slot the parent declared under the same name, and a child template has no markup outside its blocks. A page template extends the layout; a partial does not, because a partial is included into something that already has one.

C.7 Includes

src/main/resources/templates/tasks/_list.peb
<ul id="task-list" class="task-list" aria-describedby="result-count">
  {% for task in page.items %}
    {% if editingId == task.id %}
      {% include "tasks/_edit.peb" with {"task": task, "pageNumber": page.currentPage} %}
    {% else %}
      {% include "tasks/_item.peb" with {"task": task, "pageNumber": page.currentPage} %}
    {% endif %}
  {% endfor %}
</ul>
<p id="result-count">
  {% if page.totalItems == 0 %}
    No tasks{% if query %} match "{{ query }}"{% endif %}.
  {% else %}
    Showing {{ page.items | length }} of {{ page.totalItems }}{% if query %} matching "{{ query }}"{% endif %}.
  {% endif %}
</p>

include renders another template in place. The included template sees the parent's context, and with adds to it: the argument is a map literal, braces around quoted keys and values. The 2025 text taught include "x" with t=t, which Pebble rejects with Unexpected expression and the line number; the braces are not optional. Paths are relative to the loader's prefix, templates/, so a partial is always tasks/_item.peb, never _item.peb or a path with .. in it. The underscore on a partial's name is a convention for readers; the engine does not treat it differently.

C.8 When a template fails

A Pebble error names the template, the line and the column, so (tasks/_list.peb:3) means line 3 of that file. The build runs this test, which loads and renders every .peb file under templates/ with one sample context.

src/test/kotlin/TemplateSmokeTest.kt
import java.io.File
import java.io.StringWriter
import kotlin.test.Test
import kotlin.test.assertTrue

/** Loads every template through the engine, so a Pebble syntax error fails the build. */
class TemplateSmokeTest {
    private val root = File("src/main/resources/templates")

    private val sampleContext: Map<String, Any?> =
        mapOf(
            "task" to mapOf("id" to "t1", "title" to "Sample", "completed" to false),
            "page" to mapOf("items" to emptyList<Any>(), "currentPage" to 1, "totalPages" to 2, "totalItems" to 12),
            "query" to "",
            "pageNumber" to 1,
            "minTitleLength" to 3,
            "maxTitleLength" to 100,
            "message" to "Hello",
        )

    @Test
    fun `every template parses and renders with a sample context`() {
        val engine = buildPebbleEngine()
        val templates =
            root.walk()
                .filter { it.isFile && it.extension == "peb" }
                .map { it.relativeTo(root).path.replace(File.separatorChar, '/') }
                .toList()
        assertTrue("tasks/index.peb" in templates, "found only $templates")
        for (name in templates) {
            val writer = StringWriter()
            engine.getTemplate(name).evaluate(writer, sampleContext)
            assertTrue(writer.toString().isNotBlank(), "$name rendered nothing")
        }
    }
}

A syntax error therefore fails ./gradlew test before the server runs. A wrong variable name does not fail anything; it renders as an empty string, which is the strictVariables trade above.

C.9 Cheatsheet

To Write In the code
Output a value { task.title } _item.peb
Output into an attribute value="{{ addTitle }}" _add_form.peb
Leave a note {# why this line is here #} _status.peb
Branch {% if editError %}...{% endif %} _edit.peb
Branch with an alternative {% if task.completed %}Mark not done{% else %}Mark done{% endif %} _item.peb
Several branches {% if a %}...{% elseif b %}...{% else %}...{% endif %} none
Compare {% if editingId == task.id %} _list.peb
Test for a filter {% if query %} _list.peb
Loop {% for task in page.items %}...{% endfor %} _list.peb
Loop with an empty branch {% for t in items %}...{% else %}...{% endfor %} none; _list.peb uses a paragraph instead
Loop position { loop.index } from zero, loop.first, loop.last, loop.length none
Size of a list { page.items \| length } _list.peb
Encode for a URL { query \| urlencode } _pager.peb
Fall back when null { x \| default("none") } none
Change case, trim { s \| upper }, { s \| lower }, { s \| trim } none
Join strings { "a" ~ "b" } none
Arithmetic { page.currentPage + 1 } _pager.peb
Extend the layout {% extends "_layout/base.peb" %} index.peb
Fill a block {% block content %}...{% endblock %} index.peb
Include a partial {% include "tasks/_add_form.peb" %} index.peb
Include with values {% include "tasks/_item.peb" with {"task": task} %} _list.peb
Switch escaping off for one value { html \| raw } none, on purpose
Not Pebble {% empty %}, with t=t, {% endfor %} with no for, { } inside a {% %} parse errors

The Pebble documentation lists every tag, filter and test with its arguments (Pebble Templates, no date).
